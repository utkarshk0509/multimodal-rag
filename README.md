# Multimodal RAG

A Retrieval-Augmented Generation (RAG) app for asking questions about technical PDFs. You upload a PDF in the browser, it gets split into chunks and stored in ChromaDB, and then you can ask questions about it. Answers are generated by Gemini and show which pages they came from.

---

## Features

- **PDF text extraction** with PyMuPDF
- **OCR for scanned pages**: pages with no text layer are sent to Gemini Vision
- **Chart descriptions** (CLI pipeline only): Gemini describes the images extracted from the PDF
- **Semantic search** with ChromaDB and Gemini embeddings
- **Source citations**: each answer lists the retrieved passages and their page numbers
- **Voice input** using the browser's Web Speech API (works in Chrome and Edge)
- Chat history is saved in the browser's localStorage and can be exported as Markdown

---

## How it works

**Web app** (`backend_server.py`):

```
Upload PDF ─► /api/ingest
                 │  PyMuPDF reads each page (Gemini Vision OCR if a page has no text)
                 │  split into 1000-char chunks with 200-char overlap
                 ▼
              ChromaDB (one collection per uploaded file)

Question ─► /api/query
                 │  top-k similar chunks from ChromaDB
                 ▼
              Gemini LLM ─► answer + sources
```

**CLI pipeline** (for pre-processing `data/SAMPLE.pdf`, separate from the web app):

```
advanced_parser.py     ─► text chunks (JSON) + extracted images
vision_extractor.py    ─► a text description for each image
vector_store_init.py   ─► embeds both into ./chroma_db
query_rag.py / generate_rag_response.py ─► test queries
```

## Setup

Requires Python 3.10+ and a Gemini API key ([get one here](https://aistudio.google.com/app/apikey)).

```bash
git clone <repo-url>
cd multimodal-rag

python -m venv rag_env
# Windows
rag_env\Scripts\activate
# macOS / Linux
source rag_env/bin/activate

pip install -r requirements.txt
```

Copy `.env.example` to `.env` and add your key. You can also leave `.env` empty and paste the key into the field in the web UI instead.

### Run the web app

```bash
python backend_server.py
```

Open http://127.0.0.1:8000, upload a PDF, click **Build Knowledge Base**, and start asking questions.

### Run the CLI pipeline

Run these in order from the project root. They work on `data/SAMPLE.pdf`.

```bash
python data_ingestion/advanced_parser.py
python data_ingestion/vision_extractor.py
python vector_store/vector_store_init.py
python retrieval/query_rag.py
python retrieval/generate_rag_response.py
```

## Notes and limitations

- The web app stores ChromaDB and uploaded files in the system temp folder, so on Vercel/Render the indexed documents are lost when the server restarts.
- Only PDF files are supported.
- Tables are detected and counted by `advanced_parser.py`, but their text is only picked up as normal text blocks.
- The UI animations load the [Motion](https://motion.dev) library from a CDN. If it can't load, the page still works without animations.
